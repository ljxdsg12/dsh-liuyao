## 五、可选增强（**第 1 项已做**）

### 1. 声明 `tarball` 字段 —— ✅ 已做

官方明说：仓库无法从源码安装时，`tarball` 字段是**必需**的。你的仓库**恰好属于这种**——
曾实测公网 tarball 直链安装会报 `ERR_PNPM_MISSING_TARBALL_INTEGRITY`（见 `KNOWN-ISSUE-install.md`）。
有了这个字段，市场会**优先展示 tarball 安装**而不是源码构建，对用户更稳：

```yaml
tarball: https://github.com/LJXDSG12/dsh-liuyao/releases/download/v0.2.0/dsh-liuyao-0.2.0.tgz
```

官方对 `latest/download/` 有明确警告：**它只解析 `latest`，文件名按字面取**，
资产名里带版本号就会「提交当天有效、发下一版就 404」。所以这里用**钉住 tag** 的写法（如上），
带版本号的文件名在这种写法下反而是官方认可的正常做法。

**前提已满足**：v0.2.0 的 Release 已建、资产名正是 `dsh-liuyao-0.2.0.tgz`。
加之前实测过该 URL 返回 **HTTP 200**（跟随重定向后），且**下载回来与本地文件 SHA256 逐字节一致**
（`8bc9c30913e344b7a2893e31b64aec290e65c91421d3d070f2d07bf3293f94be`，438575 字节，41 个条目）。

> **顺带纠一个此前的错误结论。** 先前认为「Release 直链安装不可用」，
> 现在实测**直链安装是可用的**：`dsh plugin --profile web add <该 URL>` 首次 `Done in 5.3s`、
> 连装三次都 exit 0，写出的 lockfile 条目**带完整的 `integrity`**：
> ```
> resolution: {integrity: sha512-KzSEJkD1x8RcYXb4fpm9Q0FHw5baH7dYIqSx+0xmngSTzkRY4RJwBIM0tEVvcxz/+UMY6OhwR38/vGy6AwlEDg==,
>              tarball: https://github.com/LJXDSG12/dsh-liuyao/releases/download/v0.2.0/dsh-liuyao-0.2.0.tgz}

> 当初失败的真正原因很可能是那次**删掉旧资产、重新上传**导致 pnpm 对同一 URL 的元数据缓存与实际资产
> 对不上（换了内容、URL 没变）。**钉住 tag 之后这个隐患消失**——发新版就换 URL，不会再撞缓存。
> 另：`pnpm-workspace.yaml` 里 `minimumReleaseAge: 1440` 配了
> `minimumReleaseAgeIgnoreMissingTime: true`，正是它让「没有发布时间元数据的 GitHub tarball」

## 七、两个官方特意写长了的坑（你这插件都躲过了，记下来备用）

### 1. `dsh.client` 不等于可安装（最常见的被拒原因）

官方原话：**大多数被拒的投稿只声明了 `dsh.client`——那样无法安装。**
必须声明的是 `dsh.bundle`：

```jsonc
{
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },  // ← 必须
    "client": { "platform": "web" }               // 仅带前端 UI 时才需要
  }
}
```

你的 `package.json` 里 `dsh.bundle` 和 `dsh.client` 都有，`cordis.patch.yml` 也在仓库根，
**这条不会卡你**。以后写别的插件时注意别只写 `client`。

### 2. `peerDependencies` 的范围会静默排除预发布版 harness

这条只在你以后引用官方 `@deepseek-ai/*` 包时才相关（你现在零依赖）。

官方说明：node-semver 只有当范围里**某个比较符与该版本的 `major.minor.patch` 元组完全一致、
且自身也带预发布标签**时，才放行预发布版本。所以看起来「匹配一切」的范围其实匹配不到
`0.1.0-rc.6`，用户会撞上 `ERESOLVE`：

```jsonc
// ❌ 看着很宽，却静默排除所有 0.1.0-* 预发布版
"peerDependencies": { "@deepseek-ai/dsh-tools": ">=0.0.1-rc.1 <0.2.0" }

// ✅ 在 0.1.0 元组上显式加预发布分支
"peerDependencies": { "@deepseek-ai/dsh-tools": ">=0.0.1-rc.1 <0.1.0 || >=0.1.0-rc.1 <0.2.0-0" }
```

本机 DSH 是 `0.2.0-rc.2`，正好属于容易被静默排除的预发布版本。
